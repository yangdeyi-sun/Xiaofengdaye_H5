# 主动决策与瓶颈驱动的发展流程

开局顺序：采花蜜 → 酿蜜房 → 手动孵化、分化巢内工蜂 → 采集蜂巢房 → 手动孵化、分化采集蜂 → 侦察蜂巢房 → 手动孵化、分化侦察蜂。

- 基础转换为每秒0.6花蜜；酿蜜房18蜂蜜，无蜂蜡前置，建成即提供每秒3花蜜的加工能力。工蜂可进一步提高产能。
- 采集蜂巢房45蜂蜜，在首只巢内工蜂完成后开放；侦察蜂巢房60蜂蜜，在首只采集蜂完成后开放。
- 野花丛最大储量24、三叶草30；手动采集按实际库存扣除，采空不再产生花蜜。采空等待18游戏秒后重新开放，倒计时会存档。
- 侦察房新增花源储量、花源恢复效率两条升级。升级影响所有花源；恢复效率同时缩短正在进行的恢复等待。侦察范围、飞行速度、发现效率等属性继续保留。
- 孵化新卵按累计产卵数量计算费用，基础8蜂蜜、成长1.12倍，沿用40后的软增长，实际费用向上取整，增长在界面中可见。双卵按实际产卵数推进累计量。分化另行收费，界面显示当前费用。
- 自动产卵、自动分化、低人口紧急自动补员均已移除。旧存档的开关会被关闭，已有手动队列保留。采集、酿蜜和已开始的分化在离线期间继续。
- 侦察房建好且首只侦察蜂完成分化即结束新手引导，弹出“接下来，这个蜜蜂王国就交由你把握它的发展了”。后续新系统/事件只首次弹出说明，阅读状态持久化。
- 储蜜格在首只侦察蜂后开放，育婴房和守卫房在首次扩巢后开放，进化腔沿用过冬前置。正式四季仍从首个储蜜格开始。

旧存档保留建筑、人口、资源、队列和已开放功能；未完成引导按实际任务重算步骤，避免旧步骤编号指向错误的新目标。此前已经完成引导的存档保持完成。

验证：核心与浏览器适配测试覆盖手动繁育、离线队列、递增费用、真实花蜜库存、恢复倒计时保存与升级、完整前期流程、一次性交接。`npm run sim` 的机器人改为主动点击孵化和分化，并按新建筑顺序推进。4小时模拟验收全部通过，完成首次分蜂。

后续以本工程的测试和平台适配为准，不再运行鸿蒙一致性比较。
